# 部署检查清单 —— 部署后别的用户能用到什么

给部署者看的一页纸：**哪些功能用户开箱就能用，哪些必须先把环境搭起来，哪些纯浏览器用户根本用不了。**
用途是避免两种误判：一是以为"功能坏了"，二是以为"用户上传个文件就行"。

---

## 一、结论先说

| 结论 | 说明 |
|---|---|
| ✅ **示例小镇不用准备** | 已随应用发布（`static/data/demo_town.json`），用户点「🏘️ 载入示例小镇」即可，**零文件、零服务、零配置** |
| ✅ **城市演示不需要数据服务** | 3D 场景、资产树、实时数据面板、碳排放、LSTM 预测在 Supabase 不可用时都有本地降级 |
| ⚠️ **多源数据接入要"有东西可连"** | MySQL / PostgreSQL / InfluxDB / REST API 这四类，本质是"连你已有的数据源"。没有可连的服务，点了必然失败——**这不是 bug，是这类功能的定义** |
| ❌ **场景库、公共市场依赖 Supabase** | 未配置 `SUPABASE_URL` / `SUPABASE_KEY` 时，场景库为空、市场不可用（有提示，不会崩） |

## 二、用户视角：能点到什么

| 功能入口 | 用户需要做什么 | 纯浏览器用户 |
|---|---|---|
| 🏘️ **载入示例小镇**（场景库顶部） | **什么都不要** | ✅ 可用 |
| 3D 场景浏览 / 资产树 / 思索课件 | 无 | ✅ 可用 |
| MQTT 实时流 | 无（默认公共 broker） | ✅ 可用，但见下方"注意" |
| 导入原始数据 CSV / GeoJSON | 有自己的数据文件 | ✅ 可用（自己上传自己的数据） |
| 载入场景存档 .json | 有自己的存档文件 | ✅ 可用 |
| SQLite | 本地要有个 `.db` 文件 | ⚠️ 需要文件；**app 读的是服务端磁盘路径，不是用户本地上传** |
| MySQL / PostgreSQL | 要有个能连的库 | ❌ 纯浏览器不可用 |
| InfluxDB | 要有云账号 + token | ❌ 纯浏览器不可用 |
| REST API | 要有个能返回 JSON 数组的地址 | ⚠️ 公网地址可以，`127.0.0.1` 那种不行 |
| 场景库 / 公共市场 / 云端同步 | 需要 Supabase 已配置 | ❌ 未配置则不可用 |

> ⚠️ **SQLite 那一栏是个容易误解的点**：界面填的是"SQLite 文件路径"，由**服务端**执行
> `sqlite3.connect(path)`。所以它读的是**部署机器上的文件**，不是访问者电脑上的文件。
> 想让用户用上，文件得放在服务器上（或改成上传式导入）。

## 三、部署者视角：上线前做什么

### 3.1 必做

1. **确认示例资源在镜像里**
   ```bash
   ls -l static/data/demo_town.json        # 应有约 65 KB
   ```
   没有的话跑一次生成：
   ```bash
   python mock_data/town/build_town.py      # 会同时写 mock_data/town/ 和 static/data/
   ```

2. **确认静态服务开着**（示例资源与 3D 模型都靠它）
   ```toml
   # .streamlit/config.toml
   [server]
   enableStaticServing = true
   ```
   前端会从 `/app/static/...` 取模型和示例数据，关掉会 404。

3. **自检一遍**
   ```bash
   python mock_data/verify_mock_files.py     # 应输出「通过 90 项，失败 0 项」
   ```
   其中会校验"内置示例资源与 scene_town.json 完全一致"——防止改了小镇却忘了同步。

### 3.2 可选（按你想演示到什么程度）

| 想演示 | 要做的准备 |
|---|---|
| 实时数据跳动 | 不需要额外准备：载入示例小镇后，充电桩已有 `station_id`，面板能出模拟/预测数据 |
| **真实 MQTT 流** | 用户自己点「连接 MQTT」即可（公共 broker）。若要更稳，自建 broker 并改界面的 Broker 地址 |
| **多源数据接入** | 在**服务器上**把 mock 数据源跑起来（见 `mock_data/README.md`），并把界面里默认的 `localhost` 换成服务器可达的地址 |
| **云端场景库 / 市场** | 配 `.streamlit/secrets.toml` 里的 Supabase 凭据，并建好表（见 `core/supabase_client.py`） |

### 3.3 多用户场景下的注意点

- **示例小镇不会写云端**。点它只写当前会话（每次生成新的 `scene_id`），
  这是刻意的：否则每个用户点一下就往场景市场插一份一样的"示例小镇"。
  用户想留着，用面板里的「另存为我的场景」/「💾 保存」。
- **MQTT 用的是公共 broker**：`broker.emqx.io` 上任何人的消息都能被订阅到，
  **不要往上面发真实或敏感数据**；生产环境请换成自建 broker。
- **`mock_data/` 不是运行时依赖**。示例小镇走的是 `static/data/demo_town.json`，
  所以你可以放心把 `mock_data/` 排除在部署产物之外（但排除后就别用它的验证脚本了）。

## 四、给用户的一句话说明（可抄进帮助/FAQ）

> 打开就能看：点「📂 场景库 → 🏘️ 载入示例小镇」，立刻得到一座含 29 个充电桩的小镇，
> 不需要上传文件、也不需要配置任何服务。
> 「多源数据接入」里的 MySQL / PostgreSQL / InfluxDB / REST API 是**连接你的数据源**用的，
> 需要先有可访问的数据库或接口；没有的话不影响 3D 场景和实时数据演示。

## 五、已知限制（诚实清单）

1. **"生成模拟城市"（界面里的按钮）是纯前端的**，画出来的路网/楼是 `isHelper` 装饰物，
   不进 `scene_objects`、不落库、一次刷新就没了。做演示请用「载入示例小镇」。
2. **SQLite 路径是服务端路径**（见上文），不是用户本地上传。
3. **`lat`/`lon` 在小镇数据里存的是场景坐标**，真实经纬度在 `geo_lat`/`geo_lon`。
   原因见 `mock_data/README.md`（app 的数据库导入把这两列直接当场景坐标用）。
4. **示例小镇是"看起来对"的演示数据**，不是真实城市数据；
   充电桩利用率是构造出来的波形，别当业务结论引用。
